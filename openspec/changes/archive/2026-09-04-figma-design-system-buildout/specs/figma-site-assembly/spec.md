## Purpose

Defines a whole-page reference assembly in Figma, built from real component instances in the site's actual structure, for visual QA (spacing, alignment, color) and to prove components are genuinely reusable — kept separate from the per-component push/pull loop. Also defines a linked FigJam sitemap that cross-references the site's real structure (including the private CV subdomain and any speculative future pages) to its live URLs and Figma nodes as they get built.

## ADDED Requirements

### Requirement: The whole-page reference is composed from component instances, not copies
When assembling a whole-page reference in Figma, the system SHALL use instances of the real Figma Components (per the `figma-component-library` capability), not duplicated/detached copies of their layers.

#### Scenario: Placing a record row in the page assembly
- **WHEN** a `recordRow` appears in the whole-page reference
- **THEN** it is an instance of the `recordRow` Figma Component (or one of its variants), so editing the source Component propagates to it

### Requirement: Static, non-repeated site markup is represented without requiring a matching component file
Markup that is singular and static in `index.html` (not generated by a repeated, parameterized render function) SHALL be represented in the whole-page assembly as ordinary Figma frames, and SHALL NOT require a corresponding `components/*.js` file to exist.

#### Scenario: Representing the toolbar or hero section
- **WHEN** the whole-page assembly includes the toolbar or hero section
- **THEN** it appears as a Figma frame reflecting that markup, and no `components/toolbar.js` or `components/hero.js` file is created or expected, since neither is a repeated pattern in the render code

### Requirement: Both Desktop and Mobile layouts are represented
The whole-page reference SHALL include an assembly for the site's Desktop layout and a separate assembly for its Mobile layout, reflecting the real structural breakpoints in `styles.css`.

#### Scenario: Checking mobile spacing
- **WHEN** the owner wants to check the mobile layout's spacing or alignment
- **THEN** a Mobile whole-page assembly exists in Figma reflecting the site's actual mobile breakpoint structure

### Requirement: The whole-page assembly does not drive push/pull resync
The whole-page reference assembly is a visual-QA and reuse-proofing artifact. The system SHALL NOT treat edits made to instances within the whole-page assembly as a trigger for, or source of, a component resync — resync remains scoped to a component's own mapped node per the `design-sync` capability.

#### Scenario: An instance is moved or restyled within the whole-page assembly
- **WHEN** an instance inside the whole-page assembly is edited directly (e.g. an instance override)
- **THEN** that edit does not by itself get pulled into `components/*.js` — a resync still targets the component's own source node in `components/figma-map.json`, not its instances elsewhere in the file

### Requirement: A linked sitemap cross-references the site's real structure to its Figma representation
The system SHALL maintain a navigable sitemap (a FigJam board, distinct from the Desktop/Mobile whole-page instance assembly above — this is an information-architecture diagram, not a pixel-accurate composition) that represents every real section of the site's structure — including the private CV subdomain's export-only content and any speculative, not-yet-built page — and SHALL link each piece to its live URL or Figma node where one exists.

#### Scenario: A sitemap node has a real target
- **WHEN** a sitemap node represents a piece of the site that already has a live URL or a pushed Figma component/page
- **THEN** the node carries a working Figma hyperlink to that real target (a `https://` URL, or a `figma.com/design/...?node-id=...` deep link)

#### Scenario: A sitemap node has no target yet
- **WHEN** a sitemap node represents a piece that hasn't been built in Figma yet
- **THEN** the node is labeled with which future phase builds it, and carries no hyperlink until that phase completes — the sitemap is never left implying a link exists where it doesn't

#### Scenario: A phase builds a component or page the sitemap already anticipates
- **WHEN** a phase in `tasks.md` finishes building a component or page that the sitemap already has a placeholder node for
- **THEN** backfilling that node's real hyperlink onto the sitemap is one of that phase's own verification steps, not a separate one-time diagramming pass
