## Why

`componentize-figma-design-loop` (archived) proved the push→edit→pull loop once, on one component, as a flat frame with three hardcoded-color-turned-variables. That was deliberately minimal — enough to confirm the MCP connection, the mapping convention, and variable binding actually work live. It's not yet a design system: there's no component reuse (a flat frame can't be instanced), no representation of states (hover) or structural breakpoints (desktop vs. mobile table layout), no token coverage beyond three colors, no way to see the site assembled as a whole, and no sketch of the site's real interactivity. The owner now wants the Figma side built out to the point where every component, state, size, and token is properly represented, reusable, and ready to be edited and resynced — turning the one proven wire into an actual working design system.

## What Changes

- Represent **everything needed to render the site** as a true Figma Component — scoped by design-system completeness, not by code-side reuse. This adds atoms/organisms with no `components/*.js` counterpart: toolbar, hero (name/H1 + subtitle + bio + scroll-CTA + photo), the hide/show toggle button, the dark-mode toggle button, the scroll-CTA, an "underline text-decoration mark" atom (the `a:hover`/`.tb-btn:hover` treatment), the section header (label + toggle) promoted out of `section.js` into its own molecule, and an image-treatment pattern (hero photo's grayscale Effect Style + crop rule; favicon). `section.js`, `footerLink.js`, and `paragraphBlock.js` each also become their own top-level Figma Component.
- Convert the existing flat-frame `recordRow` push (node `2:6` in file `Z5ovK9oyPY12Y4cMkexbHq`) into a real `COMPONENT_SET` with `state` (Default/Hover) and `breakpoint` (Desktop/Mobile) variant axes, composed from nested `statusDot`/`entityBlock` instances mirroring `recordRow.js`'s call graph, using **component properties** (TEXT/BOOLEAN) for its content fields rather than static text — so every instance can carry different real content, or a synthetic stress-test string, without detaching from the master. Real content (`VYOLA CYANA`/`IT WAS RAINING`/`MAILIN` — short/medium/long) ships as default instances; a small set of synthetic short/medium/heavy text presets is built alongside for stress-testing any text-sensitive component, not just `recordRow`.
- Document a full interactive-state matrix (toolbar button, hide/show toggle, inline links, `recordRow`, status dot, the `{wip}` marker) and the instance-override/master-propagation discipline that makes per-instance content variation safe without breaking reusability.
- Elevate a hard redesign-proofing rule: no pushed component may hard-code a color/size/spacing value that already has a token, and auto-layout is used throughout — protecting the same "one `content.md`, everything renders automatically" property the codebase already has, applied to the design side.
- Expand the "Design Tokens" variable collection from its current 3 ad hoc colors to the full `styles.css` `:root` token set, using Figma variable **modes** (Desktop/Mobile) for each fluid `clamp()` token's static endpoints (formula documented per variable), plus a `FONT_FAMILY`-scoped typeface variable (verified live — see design.md). Add Figma **Text Styles** for every type role the site uses, bound to those variables, and build a "Foundations" page presenting the whole system.
- Structure the Figma file as a **"Core" (generic, theme-agnostic) vs. "Theme — EstebanCuenca CV" (this project's real tokens/content) page split**, so it's copy-paste-portable to another project by hand today, and trivially becomes a published Team Library if the plan is ever upgraded (verified live: the current Starter plan cannot publish libraries — see design.md).
- Add a dedicated "Ideas / Unused" page and a `status` field (`active`/`idea`/`deprecated`/`speculative`) on each `components/figma-map.json` entry, so exploratory or not-yet-adopted components have a clear home and are explicitly excluded from resync targeting.
- Assemble a whole-page reference (Desktop and Mobile) from **instances** of the real components, in the site's actual order, so spacing/alignment/color can be checked visually and components proven reusable.
- Sketch three real site interactions as Figma prototype flows: dark/light toggle (via Figma's native "Set variable mode" action — a close match for the site's actual token-swap mechanism), section hide/show (Smart Animate), and row hover.
- Extend `components/figma-map.json`'s existing schema (not a new mechanism) to track variant/instance node IDs and the new `status` field.
- Document, but explicitly do **not** resolve, two real content-model decisions surfaced by this work: per-project media (images/video beyond the single global hero photo — no `content.md` schema exists for this yet) and content-surface differentiation (what shows on the web table vs. the CV/print table vs. a possible future per-project detail page — e.g. Education's web visibility, MAILIN's synopsis). Both are flagged as tracked Open Questions in design.md, with a Figma-side convention (a named image slot; a speculative "Project Detail" template) built ahead of the decision without pre-empting it.
- **BREAKING**: none — same non-destructive constraint as the archived change. No visual or behavioral change to the deployed site without explicit owner approval; this work is entirely Figma-side plus `components/` authoring conventions.

## Capabilities

### New Capabilities
- `figma-component-library`: true Figma `COMPONENT`/`COMPONENT_SET` nodes (with state/breakpoint variants and nested sub-components) representing each `components/*.js` file, replacing ad hoc flat-frame pushes.
- `figma-token-foundations`: the full token-to-Variable(-mode) mapping, Text Styles, and a documented Foundations page in the Figma file.
- `figma-site-assembly`: a whole-page reference (Desktop + Mobile) built from real component instances, for visual QA and reuse — not part of the push/pull loop itself.
- `figma-interaction-sketch`: prototype-flow sketches of real site interactions, and the discipline for reading `node.reactions` back as translation input (not codegen) during a resync.

### Modified Capabilities
- `design-sync`: extend the existing push/pull/mapping requirements to cover pushing component variants (not just single frames), pulling per-variant/per-mode values, and reading interaction reactions — using the same drift/guesswork reporting discipline already established.

## Impact

- **Affected**: the Figma file(s) under the `EstebanCuenca` team (reused from the archived change — same team, same non-destructive constraint), `components/figma-map.json` (schema extended for variants/instances/status), `components/README.md` (documented alongside the existing mapping convention).
- **Not affected**: `index.html`, `styles.css`, `content.md`, or any other live-site file — this change is Figma-side design-system construction, not a site code change. Any future component regeneration from a resync remains a separate, explicitly-approved step per the `design-sync` capability's existing "no visual change without approval" requirement.
- **Process**: phase-by-phase, stopping for explicit owner confirmation between phases — the same working style used throughout the archived change, per the owner's stated preference.
